# tree-sitter grammars and queries

Corvane's opt-in tree-sitter highlighter (Settings › Appearance › Syntax
highlighting, flag `105-tree-sitter-highlighting`) takes its grammars from
`crates/corvane-grammars` and its highlight queries from
`crates/corvane-grammars/queries/<grammar>/`. Everything about a grammar lives
in `languages.toml`; two scripts derive the rest.

| File | Written by |
|---|---|
| `crates/corvane-grammars/queries/<grammar>/{highlights,injections,locals}.scm` | `sync.py` |
| `crates/corvane-grammars/THIRD_PARTY.md` (grammar + query licenses, shipped in the packs) | `sync.py` |
| `crates/corvane-grammars/Cargo.toml`, `src/grammars.rs`, `sources.txt` (features, deps, the grammar table, `REST`, the source-built list) | `gen.py` |
| `tools/ts-queries/sources.lock.json` (sha256 and C entry point of every source-built grammar) | `fetch.py` |
| `target/grammar-src/<grammar>/` (their `src/`, `queries/`, metadata; not in git) | `fetch.py` |
| `docs/reference/tree-sitter-languages.md` | `cargo test -p corvane-highlight --test treesitter languages_doc` with `UPDATE_TS_LANGUAGES_DOC=1` |
| `crates/corvane-highlight/tests/ts/expected/*.spans` | the same test file's `golden_spans` with `UPDATE_TS_GOLDEN=1` |

## Two kinds of grammar

- **Crates** (`package` + `version`): crates.io grammar crates, resolved by cargo.
- **Source-built** (`url` + `revision`): grammars without a usable crate (none
  published, or Rust bindings that pin an older tree-sitter). `fetch.py`
  downloads the pinned GitHub tarball (sha256 in `sources.lock.json`) and
  extracts `src/` + `queries/`; corvane-grammars' `build.rs` compiles
  `parser.c` and the scanner and sets `cfg(corvane_src = "<name>")`. Without
  fetched sources they are skipped, so a plain checkout still builds and
  tests. `import_nvim.py` added nvim-treesitter's parser list this way, at
  nvim-treesitter's pinned revisions, so its queries match (GPL / LGPL
  grammars are skipped). Grammars that do not commit `parser.c`
  (`generate = true`: latex, perl, pod, teal, unison, mlir, ocamllex) are
  generated by `fetch.py` with tree-sitter CLI 0.27.0 (`CORVANE_TREE_SITTER`,
  else `tree-sitter` on PATH; node evaluates `grammar.js`).

`gen.py` refuses two grammars claiming one file type.

## Pack units

`packaging/packs.sh` builds one library per unit (a crate's grammars, or one
source-built grammar) with `build_unit.py`: clang compiles the parser(s),
scanner(s) and a generated C table with corvane-grammars' layout (`ABI` 1),
no Rust. The pack is those libraries gzipped plus `index.json` (`gen.py
--index`), so the app can detect languages without opening any library.

## Adding or bumping a grammar

1. Add a `[name]` table to `languages.toml`: `package` + `version` (crates.io),
   `language` (the package's `LanguageFn` constant) or `symbol` (its C
   function, for packages with pre-0.23 bindings), `extensions`,
   `filenames`, `first_line`, `aliases`, `source`.
   A package may depend on `tree-sitter` only in a version that resolves to
   corvane-highlight's (cargo refuses a second copy of the C runtime).
2. `python3 tools/ts-queries/sync.py --candidates <name>` and
   `cargo run -p corvane-highlight --example ts-queries` to compare the query
   sources, then set `source` (rule below).
3. `python3 tools/ts-queries/sync.py <name>` and `python3 tools/ts-queries/gen.py`.
4. Add `crates/corvane-highlight/tests/ts/samples/sample.<ext>` when no
   sample of the language exists (tests/cm/samples counts too), then
   `UPDATE_TS_GOLDEN=1 UPDATE_TS_LANGUAGES_DOC=1 cargo test -p corvane-highlight --test treesitter`
   and review the new golden file.

`python3 tools/ts-queries/sync.py --check` and `gen.py --check` fail when a
generated file is stale.

## Which queries

Preference (decided 2026-09-30): nvim-treesitter first (Apache-2.0; the most
maintained set, and several grammars' own queries are older copies of it), then
the grammar package's own queries (usually MIT), then Helix (MPL-2.0), then a
hand-written query in `corvane/<name>/` using Zed's capture names. A source
is used only when it compiles against the pinned grammar version (nvim and
Helix track newer grammar revisions than crates.io has) and does not colour
nearly everything with one class (the Haskell grammar's own query ends in
`(variable) @type`). Zed's own queries are GPL-3.0 and only serve as a naming
reference.

`sync.py` rewrites nvim-treesitter and Helix queries for Corvane's painter:

- `; inherits: a,b` is resolved by prepending the parents' files;
- `#lua-match?` / `#vim-match?` become `#match?` (Lua patterns and magic Vim
  regexes translated); predicates tree-sitter cannot evaluate are dropped and
  noted in the file header, and nvim's `(#set! @node key @other)` directives
  are removed (tree-sitter takes string values only);
- Helix files are reversed pattern by pattern: Helix lets the first matching
  pattern win, Corvane (like tree-sitter-highlight and Neovim) the last.

Additions Corvane needs on top of a source go in `patches/<name>/<kind>.scm`
(MIT); `sync.py` appends them.

## How captures become colours

`crates/corvane-highlight/src/treesitter/captures.rs` maps capture names
(Zed's, nvim's and Helix's vocabularies) onto GitHub Desktop's thirteen
`--syntax-*` colours by longest dot-prefix; `docs/reference/tree-sitter-captures.md`
is the generated table. The painter applies nvim's `#set! priority`, paints
outer nodes before inner ones and later patterns over earlier ones, and
paints injected languages over their host. An injection's content excludes
the node's named children unless `injection.include-children` is set
(Neovim's rule).

## Packs

`packaging/packs.sh` assembles `tree-sitter-all` (every unit) and
`tree-sitter-rest` (the units of languages GitHub Desktop does not highlight
at all, plus the injection-only grammars they use) per macOS architecture,
ad-hoc signed, with `THIRD_PARTY.md`. Manifest entries carry
`target = "macos-aarch64"` / `"macos-x86_64"`.
