# Deviations from GitHub Desktop 3.6.6

Features Corvane has that behave or look slightly differently from GHD, with the reason. Unbuilt features are in `TODO.md`; each module's doc comment also names its deviations next to the GHD file it ports.

## Flags

- Every deviation that can be switched off is a flag (`flags.md`, generated from `crates/corvane-core/src/flags/registry.rs`): a bullet below that ends with "Flag: `NNN-slug`" is controlled by that flag, and the **GitHub Desktop** preset turns all of them to their GHD-exact value. The rest of this file (engine, layout and platform decisions) stays fixed; `flags.md` lists them under "Not toggleable".
- The Flags dialog itself (`crates/corvane-ui/src/dialogs/flags.rs`, Corvane › Flags…, ⌘⇧,, `x-corvane://flags?q=`, `CORVANE_POPUP=flags[:query]`) is a Corvane addition with no GHD counterpart: search, category navigation, presets, per-flag Reset, a Relaunch bar for restart-required flags, Copy / Paste as JSON and `CORVANE_FLAGS`. `CORVANE_FLAGS` locks the flags it names for one session; the parity harness runs with `preset=github-desktop`. Each flag is a feature or a bug fix (`Nature` in the registry, tagged in `flags.md`); bug fixes are hidden from the dialog's list, search and counts unless its "Show bug fixes" checkbox (per dialog session, off by default) is ticked, while presets, Reset all and `CORVANE_FLAGS` still apply to them. An All / On / Off switch narrows the list and counts the same way to flags that deviate from GitHub Desktop (any value but the GitHub Desktop preset's) or do not. A Presets page lists each preset with its details, how many flags and bug fixes it switches on and how many of your current values it would change; Reset all, and picking a preset while flags are modified, ask first in a sheet over the dialog. The list is virtualized, so only the rows on screen are laid out each frame.

## GitHub layer

- **CI check runs**: GHES version gating (`lib/endpoint-capabilities.ts`) is reduced to GitHub.com vs. Enterprise (Enterprise gets no re-run and no Actions job steps). Views subscribe to a ref's status by touching it while rendering (`Dispatcher::touch_commit_status`, never notifies); a key nobody rendered for five minutes stops refreshing (GHD subscribes on mount / unsubscribes on unmount). Flag: `308-ci-status-idle-minutes`.
- **Pull request cache** is keyed by endpoint + `owner/name` in redb (`pull-requests:<key>`) with the head/base repositories embedded in each record; GHD keys IndexedDB rows by the GitHub repository's database id.
- **Push Branch Commits** (before a pull request is created): the base branch picked in Preview Pull Request survives the push (GHD's `onConfirm` drops it), and a failed push leaves its error on screen instead of opening the compare page anyway. Flags: `304-push-branch-commits-keeps-base`, `305-push-branch-commits-error-stops`.
- **Forks**: the repository's API `permissions` are refreshed on selection and after signing in (as GHD) and persisted with the repository. A push to a repository the user can only read opens `CreateFork` before git runs (GHD runs the push and offers the fork after the authentication failure); repositories whose permissions were never fetched still get the fork offer after a push refused with "Permission denied". The remote URL is not rewritten when the API reports a renamed repository (GHD `updateRemoteUrl`). Flag: `303-fork-before-push`.
- **Repository rules**: `useRepoRulesLogic` needs the account plan; an account stored before Corvane read it counts as paid until the launch refresh fills it in. The commit-message check merges the `Co-Authored-By` trailers with a port of `git interpret-trailers`' block rules instead of spawning git on every keystroke.
- **Re-authorization** (`workflow` scope, SAML SSO, invalidated token) opens the sign-in dialog (its default flow follows `307-sign-in-flow`) instead of GHD's browser flow; the push / failed action is retried after signing in, as in GHD.
- **Sign-in flows** (`docs/technical/oauth.md`): the browser flow is the default on GitHub.com only when the build has a client secret (`CORVANE_GITHUB_CLIENT_SECRET`); otherwise, and on GitHub Enterprise, the device flow is (GHD only has the browser flow, with a bundled client secret). "Use the browser flow instead" runs GHD's web application flow with PKCE and a CSRF state over the `x-corvane-auth://oauth` callback (loopback `http://127.0.0.1:<port>/callback` for a bare binary or `CORVANE_OAUTH_LOOPBACK=1`); without `CORVANE_GITHUB_CLIENT_SECRET` at build time the token exchange relies on PKCE alone and GitHub refuses it (`incorrect_client_credentials`, seen live 2026-10-01). Flag: `307-sign-in-flow` (which flow the primary button starts — auto, device or browser; the other stays a link away).
- **GitHub Enterprise sign-in** (`ui/sign-in/sign-in.tsx`, `lib/stores/sign-in-store.ts`): GHD signs in to GHES in the browser with its own OAuth app. A GHES server does not know Corvane's github.com app, so the host needs an OAuth app its administrator registered (callback `x-corvane-auth://oauth`, Enable Device Flow for the device flow, GHES 3.1+). Its client ID comes from the sign-in dialog's "OAuth app" step (remembered per host in the store, client secret in the Keychain as `oauth:<client id>@<host>`) or is built in with `CORVANE_GHES_OAUTH=host=client_id[:secret],…`. With one, GHES offers the same device / browser / token choices as GitHub.com; without one, the dialog goes from the address straight to a personal access token, with a link to enter an app. Unverified live (no GHES instance).
- **Pull request notifications** (`corvane_core::notifications`, `corvane_platform::notifications`): posted through `UNUserNotificationCenter` with GHD's titles and bodies; the click handler follows GHD's app-store callbacks (select the repository when none is, then the review / comment / checks-failed dialog, or the CI popover when the pull request's branch is checked out). The notification's `userInfo` carries the dialog's data as JSON, so a click from an earlier session opens the dialog without GHD's API re-fetch. Posting needs the app bundle outside temporary directories (macOS answers "Notifications are not allowed for this application" for a bundle under `/private/tmp`).
- **Alive events** (`corvane_core::alive`, `corvane_github::alive`; GHD `alive-store.ts` + `notifications-store.ts` over `@github/alive-client`): one WebSocket subscription per signed-in GitHub.com account while Settings › Notifications is on, to the channel `/desktop_internal/alive-channel` names, with the offset kept across reconnects (exponential backoff capped at ten minutes; the JavaScript client's presence channels, shared worker and "Alive Redeploy" early reconnect are not implemented). Events are handled as in GHD: only the selected repository (a fork's parent when contributing upstream), only pull requests already in the cache, the review / comment / checks fetched from the API, checks-failed only for commits the account's emails authored and once per check suite. `CORVANE_POPUP=alive:<kind>[:api]` feeds a sample event through the same handler (sample review / comment / checks unless `:api`). Unverified live: no account exists on the development Mac, so the socket handshake against GitHub's Alive service has only been exercised by the frame parser's tests.
- **Test Notifications** (`dialogs/test_notifications.rs`, Help › Show Test Notifications in debug builds, `CORVANE_POPUP=test-notifications`): each button posts a sample notification at once (`corvane_core::samples`) instead of GHD's pick-a-pull-request / pick-a-review steps over the API, so there is no Back button; it works for repositories without a GitHub remote (a stand-in repository is used). As in GHD, test notifications ignore Settings › Notifications.
- **Pull request notification dialogs** (`PullRequestReview`, `PullRequestComment`, `PullRequestChecksFailed`, `crates/corvane-ui/src/dialogs/pull_request_notifications.rs`) open from a notification click, or with sample data through `CORVANE_POPUP=pr-review|pr-comment|pr-checks-failed|notification-click:<kind>`. "Switch to Pull Request" closes the dialog before switching (GHD spins in the header until the checkout is done); checks-failed shows the job steps the commit status store already has (no "Stand By" pane while logs load); re-running replaces the dialog, since Corvane shows one popup at a time.
- **Cherry-pick onto a pull request** (`pull_request_row` drop target, `Dispatcher::cherry_pick_to_pull_request`; GHD `onDropOntoPullRequest` + `startCherryPickWithPullRequest`): commits dragged from History onto a row of the Pull Requests tab are copied onto the pull request's branch, found the way a checkout finds it (a fork remote is added and fetched, `pr/<n>` created). Dropping on the checked-out pull request does nothing, as in GHD. When the branch cannot be determined GHD only logs and ends the operation; Corvane also shows the reason (Flag: `306-cherry-pick-pr-branch-error`). The cherry-pick operation starts at the drop (GHD starts it when the drag begins).
- **Pull request quick view** (`crates/corvane-ui/src/pull_request_list.rs`): the card is a fixed 400 px wide (GHD's `min-width`), shows the list item's "opened … by author" line next to the `#N` badge (Corvane addition), and is positioned from the card height measured on the previous frame instead of staying hidden until the Markdown iframe has loaded. Flags: `301-pr-quick-view-opened-by`, `302-pr-quick-view-width`.
- **Clone dialog** caches the repository list in redb per endpoint and filters it locally (as GHD does); there is no server-side search.
- **Clone dialog** resolution (`corvane_core::clone_info`): when every account answers 404 for an `owner/name` shorthand, Corvane shows GHD's "We couldn't find that repository" error (GHD passes the bare alias to git, which fails); when a lookup fails otherwise (offline, anonymous rate limit) the shorthand is cloned as `https://github.com/owner/name.git` (Flag: `204-clone-shorthand-not-found`). The account picker's filter is a fuzzy match on login and endpoint, and the list has no keyboard navigation.
- **SSH fork remotes**: when the repository's remote is SSH (`user@host:path` or `ssh://`), Create Fork's new origin, the `upstream` remote (added, or updated from `UpstreamAlreadyExists`, whose Expected URL follows) and the `github-desktop-<owner>` remote a fork pull request checkout adds use the same SSH user and host with the API repository's path (GHD `_convertRepositoryToFork`, `addUpstreamRemoteIfNeeded`, `_findPullRequestBranch` always use the HTTPS `clone_url`). Flag: `309-fork-remotes-keep-ssh`.
- **Check runs**: a commit's check runs are read page by page (`page=`, up to 1,000) until `total_count` are in (GHD `fetchRefCheckRuns` reads one page of 100, so repositories with more checks show a partial status). Flag: `317-all-check-run-pages`.
- **URL actions** (`x-corvane://openRepo`, `crates/corvane-core/src/app_url.rs`): a repository whose GitHub repository is the URL wins over a fork that matches through its parent (GHD `doesRepositoryMatchUrl` takes the first match in list order). Flag: `312-exact-repository-url-first`.
- **Publish errors**: a failed Publish Repository shows GitHub's validation `errors[].message` in parentheses after the top-level message (`corvane_github::Client::with_error_details`; GHD's `APIError` keeps `message` only, so a too-long description reads "Repository creation failed."). Flag: `311-api-error-details`.
- **Forking disabled**: the repository's API `allow_forking` is stored with its record; when it is `false` the commit form's "create a fork" warning, `CreateFork` before a push and the fork offer after a refused push are skipped, and the push runs or fails as usual (GHD `showNoWriteAccess` / `insufficientGitHubRepoPermissions` ignore it and the fork request fails). Flag: `310-fork-offer-respects-allow-forking`.
- **Re-run checks**: the check-run popover hides Re-run and the per-job re-run when the stored record of the pull request's base repository says the account can only read it (GHD `CICheckRunPopover` shows them and the request fails). Flag: `318-rerun-needs-push-access`.
- **Pull Requests tab signed out**: with no account for the repository's endpoint the empty tab shows "Sign in to see pull requests" with a Sign in link (the `SignIn` popup for GitHub.com or Enterprise) and the refresh button is disabled; cached pull requests still list (GHD `NoPullRequests` says "You're all set!" and the refresh button does nothing). Flag: `315-pull-requests-signed-out`.
- **Plain-HTTP Enterprise**: an Enterprise address typed with `http://` keeps plain HTTP for the API, the sign-in flows and web links (`Endpoint::enterprise(_, allow_http)`); off except in the Everything preset, since the token is then sent unencrypted (GHD forces HTTPS since 3.4.7). Flag: `314-enterprise-plain-http`.
- **Pull requests from deleted forks**: open pull requests whose head repository is `null` stay in the list; checking one out fetches `refs/pull/<n>/head` from the base repository's remote into `pr/<n>` (reused when it exists) (GHD `pull-request-store` drops them). Flag: `316-pull-requests-from-deleted-forks`.
- **Issue suggestions**: the `#` issue cache fetches every open issue again (replacing the cache) once the flag's hours have passed since the last full fetch, so deleted and transferred issues stop being suggested (GHD `IssuesStore.refreshIssues` only asks for issues updated since the newest cached one). Flag: `320-issues-full-refresh-hours`.
- **Checks popover**: the header's summary line ends with an "Open #N on GitHub" link to the pull request (GHD `ci-check-run-popover.tsx` has none). Flag: `319-ci-popover-pull-request-link`.
- **Clone dialog** can clone over SSH: a repository picked from the list or an `owner/name` shorthand is resolved to its SSH URL; an `https://` URL typed on the URL tab keeps HTTPS (GHD clones over HTTPS unless an SSH URL is typed). Flag: `226-clone-prefers-ssh`.
- **Clone dialog** and the signed-in blank slate: a repository URL pasted into the repository filter (`https://github.com/owner/name`, `git@host:owner/name.git`, a browser URL into the repository) filters as `owner/name`; GHD fuzzy-matches the whole URL and finds nothing. Flag: `227-clone-filter-accepts-urls`.
- **Clone dialog** and the signed-in blank slate: the account picker can start on a chosen account (a list of logins; the first one signed in for the tab wins) instead of the first account signed in. Flag: `228-clone-default-account`.
- **Clone dialog** can show a "Shallow clone (only the latest commit)" checkbox under the local path that clones with `git clone --depth 1` (GHD always clones the full history). Flag: `233-shallow-clone`.
- **Clone dialog** can suggest `<clone folder>/<owner>/<name>` as the local path (GHD: `<clone folder>/<name>`); git creates the owner folder. Flag: `230-clone-path-includes-owner`.
- **Clone dialog**: when the local path is already a Git repository, a line under the path offers "Add this repository instead?" (as Create a New Repository does); GHD only says the folder contains files. Flag: `231-clone-offer-add-existing`.
- **Clone dialog**'s URL tab takes a local repository (`/path`, `~/path`, `file://` URL): the suggested local path is named after the folder and a path without a repository shows "There's no Git repository at that path" before git runs. GHD takes `/a/b` for the GitHub repository `a/b` and rejects longer paths. Flag: `232-clone-local-sources`.
- **Clone dialog**: a failed clone reopens the dialog on the URL tab with the same URL and local path and git's error in the banner; GHD shows a "Clone failed" error dialog and the input is lost. Flag: `235-clone-failure-keeps-input`.
- The Current Repository toolbar button can show a GitHub repository's owner in place of "Current Repository" (Corvane option), so same-named forks are told apart. Flag: `409-owner-in-repository-button`.
- The repository list's filter button can offer Forks / Not forks (GitHub's fork flag; local repositories count as not forks); the Recent group is left out while one is on. Flag: `208-repository-fork-filter`.
- The clone dialog and the blank slate's repository list can leave out the repositories of chosen owners (comma-separated logins; empty by default, Corvane addition). Flag: `229-hidden-clone-owners`.

## Repository

- Filesystem watcher (Corvane addition, `corvane_core::watcher`; GHD only refreshes on window focus and after its own actions): FSEvents on the selected repository's worktree and `.git`, debounced 300 ms, trigger a refresh. Worktree paths git ignores do not count unless the index tracks them (gitoxide's exclude stack: the `.gitignore` files, `.git/info/exclude`, `core.excludesFile`; rebuilt when one of them, the config or the index changes), so a build writing into `target/` or `node_modules/` does not refresh every debounce window. Flags: `202-fs-watcher`, `904-fs-watcher-debounce-ms`.
- Add Local Repository checks the path as it changes and keeps Add Repository disabled until it is a repository; GHD 3.6.6 checks only when Add Repository is pressed and leaves that warning up, stale, while the path is edited. Flag: `205-add-local-validates-while-typing`.
- Add Local Repository › Choose… can select several folders; with more than one it adds each folder that is a Git repository and names the others in an error (GHD's picker takes one folder). Flag: `222-add-local-multiple`.
- Add Local Repository's Local Path autocompletes folder names (`/…`, `~/…`; the Add Worktree branch popup with folder rows: ↑/↓, Enter/Tab, Esc); GHD's box is plain text. Flag: `223-add-local-path-completion`.
- Create a New Repository, Add Local Repository and Clone a Repository can show an optional Alias field; the alias is kept per path (`Dispatcher::alias_when_added`) and applied when that repository is added, dropped if the create or clone fails. GHD sets aliases afterwards only. Flag: `224-alias-when-adding`.
- The discard confirmation leaves out "Changes can be restored by retrieving them from the Trash" when every discarded entry is a submodule (nothing goes to the Trash); GHD 3.6.6 always shows it. Flag: `721-discard-submodule-no-trash-hint`.
- Import Repositories from GitHub Desktop (Corvane addition, off in the Corvane preset; File menu, a fifth button on the "Let's get started!" page when GitHub Desktop's data is on the Mac, `CORVANE_POPUP=import-ghd`): `corvane_platform::ghd_import` reads GHD's IndexedDB LevelDB files directly (write-ahead logs, sorted tables, snappy; newest entry per key, deletions honoured, GHD may keep running) and picks the `repositories` records out of the V8-serialised values; the dialog lists the ones still on disk that Corvane lacks, all ticked, and adds the ticked ones in GHD's order with their aliases. `CORVANE_GHD_DATA_DIR` points it at another GHD profile. Best effort: an unreadable file or a changed record layout yields fewer (or no) repositories, never an error. Flag: `206-import-from-github-desktop`.
- Taller text boxes: Repository Settings › Ignored Files' .gitignore box is 260 px tall (GHD `textarea.gitignore { height: 130px }`, `app/styles/ui/_repository-settings.scss`) and the Squash dialog's description shows 12 lines (GHD 6). Flag: `107-taller-text-areas`.
- Repository Settings › Remote (`app/src/ui/repository-settings/remote.tsx`) shows the `upstream` remote's URL, read-only, under the primary remote when one exists. Flag: `236-upstream-remote-in-settings`.
- Repository Settings › Ignored Files (`app/src/ui/repository-settings/git-ignore.tsx`) adds an "Add a template" list of the bundled `.gitignore` templates: a pick fills an empty box, or is appended under a `# <Name>` line; nothing is written until Save. Flag: `237-gitignore-templates`.
- Worktree list (`app/src/ui/worktrees/worktree-list-item.tsx`): rows have a tooltip with the name and full path, and the filter also matches the path, so worktrees with the same folder name can be told apart. Flag: `240-worktree-paths`.
- New Worktree's default location (GHD's Add Worktree dialog uses the clone directory) is a template: `{clone-dir}` (the default, GHD's behaviour), `{repo}` and a leading `~` (e.g. `~/code/worktrees/{repo}`). Flag: `241-worktree-location`.
- Selecting another repository while a dialog for the current one is open (from a link, the command line tool, a notification) closes that dialog (`Popup::repository`); conflict and credential prompts of an operation in progress stay. GHD keeps the dialog over the new repository (`app/src/lib/stores/app-store.ts` `_selectRepository`). Flag: `218-close-dialogs-on-repository-switch`.
- Repository › Add License… (Corvane addition, off in the Corvane preset): picks one of the license templates Create a New Repository offers and writes it to `LICENSE` in the repository, filled in with the global Git name / email, the folder name and the year (`corvane_core::templates::write_license`). It never replaces a file: any `LICENSE*`, `LICENCE*` or `COPYING*` already there is an error, and the file is created exclusively. GHD offers licenses only when creating a repository. Flag: `221-add-license`.
- Create a New Repository can create the repository in the Local Path folder itself ("Create the repository in this folder (no subfolder)"); GHD always creates a `<name>` subfolder. In that mode a README.md, .gitignore or LICENSE already in the folder is kept, not replaced; everything in the folder goes into "Initial commit" as in GHD. Flag: `220-create-repository-in-folder`.
- A failed force push keeps the branch's "Force push" recommendation (`Dispatcher::push_then` clears it after a successful push); GHD's `performPush` clears it before the push runs, so after a failure the button falls back to a plain Push that git rejects. Flag: `258-force-push-kept-on-failure`.
- Background fetch (`Dispatcher::background_fetch_tick`; GHD `BackgroundFetcher`, GitHub repositories only): can be turned off, or extended to any repository with a remote (the GitHub Desktop value stays the default). Flag: `244-background-fetch`.
- Fetch can prune tags (`corvane_git::fetch_with_prune_tags`, `--prune-tags`; GHD's `fetch` prunes branches only, so a tag deleted on the remote stays): off by default because it also deletes local tags that were never pushed; skipped while tags created in Corvane wait to be pushed. Flag: `248-fetch-prune-tags`.
- The cloning view has a Cancel button (`Dispatcher::cancel_clone`, `corvane_git::CancelToken`): it sends `git clone` SIGTERM, so git removes the directory it created, and no error is shown. GHD (`cloning-repository.tsx`) has no way to stop a clone, and removing the cloning repository leaves git downloading. Corvane never lists the cloning repository in the sidebar, so there is nothing to remove. Flag: `234-clone-cancel`.
- Background fetch without a busy button (Corvane addition, off in the Corvane preset): the background fetch shows no progress in the push/pull button, and a push, pull or fetch requested meanwhile waits for it and then runs (`Dispatcher::after_network`); GHD's `withPushPullFetch` shows the fetch's progress, disables the button and drops a push from the menu. Flag: `245-push-during-background-fetch`.
- Reset to remote (Corvane addition, off in the Corvane preset): the push/pull dropdown offers "Reset to <upstream>" while the branch has commits its upstream lacks; a warning dialog names the commits and uncommitted changes that will be discarded, then `reset --hard refs/remotes/<upstream>` runs (the commits stay in the reflog). GHD has no such command. Flag: `261-reset-to-remote`.
- Update a branch from its upstream (Corvane addition, off in the Corvane preset): the branch context menu's "Update from <upstream>" on a local branch that is not checked out runs `fetch <remote> refs/heads/<b>:refs/heads/<local>` (`corvane_git::fast_forward_branch_from_remote`), which only fast-forwards; a diverged branch gets an error that says to check it out and pull. GHD's `generateBranchContextMenuItems` has no such item. Flag: `857-update-branch-from-upstream`.
- Repository › Fetch All Repositories (Corvane addition, off in the Corvane preset): fetches every listed repository that has a remote, one after another on a background thread, without progress in the push/pull button, skipping repositories with a push, pull or fetch running; failures are listed in one error dialog at the end, then the selected repository and the sidebar indicators refresh (`Dispatcher::fetch_all_repositories`). GHD's menu (`build-default-menu.ts`) fetches the selected repository only. Flag: `247-fetch-all-repositories`.
- "Last fetched" after a clone: a repository not fetched since it was cloned takes the clone's time from `HEAD`'s first reflog entry ("clone: from …", `corvane_git::cloned_at`); GHD's `updateLastFetched` reads `FETCH_HEAD` only, which a clone does not write, so the push/pull button says "Never fetched". Flag: `253-clone-counts-as-fetch`.
- Plain-language remote errors (`push_errors::plain_remote_error` / `plain_clone_error`): a pull or fetch whose upstream branch no longer exists on the remote ("Your configuration specifies to merge with the ref …", "couldn't find remote ref") and a clone into a folder without write permission get an explanatory sentence before git's message; GHD shows git's text only. Flag: `255-plain-language-remote-errors`.
- Repository list indicators refresh one second after launch and when the repository list opens (at most once a minute, `Dispatcher::refresh_indicators_if_stale`), besides every 15 minutes; GHD's `RepositoryIndicatorUpdater` only runs on its delayed periodic cadence. Flag: `217-prompt-indicator-refresh`.
- After a pull, `git remote set-head -a` (GHD `updateRemoteHEAD`, which lists every ref on the server) runs only when `refs/remotes/<remote>/HEAD` does not resolve (`corvane_git::remote_head_resolves`); a remote whose default branch changed is picked up once the old branch is pruned. Flag: `251-remote-head-once`.
- Fetch can pass `--write-commit-graph` (`corvane_git::FetchOptions`), extending the commit-graph file that speeds up history walks and ahead/behind counts; GHD's `fetch` never does. `--no-write-fetch-head`, also proposed upstream, is not used because "Last fetched" reads `FETCH_HEAD`. Flag: `249-fetch-writes-commit-graph`.
- Fetch and pull can leave submodules alone (`--no-recurse-submodules`; GHD's `fetch` passes `--recurse-submodules=on-demand` and `pull` `--recurse-submodules`), off by default. Flag: `250-sync-skips-submodules`.
- The background fetch can fast-forward the checked-out branch (`corvane_git::fast_forward_if_only_behind`, `merge --ff-only @{upstream}`) when it is behind but not ahead, the working directory is clean and no merge, rebase or cherry-pick is in progress; off by default. GHD's background fetch never touches the checked-out branch. Flag: `246-background-fetch-fast-forwards`.
- Force push is recommended after a rewrite outside Corvane: when the current branch is ahead of and behind its upstream and the upstream's tip is in the branch's reflog (`corvane_git::upstream_tip_in_reflog`: the pushed commits were amended, rebased or reset away, not replaced by someone else's push), `getCurrentBranchForcePushState` answers Recommended, so the button offers Force push (with its confirmation) instead of Pull. GHD recommends it only after its own amend or rebase (`forcePushBranches`). Flag: `260-force-push-after-outside-rewrite`.
- A fetch or pull that fails because a stale remote-tracking ref blocks a new one ("cannot lock ref", "unable to update local ref", `corvane_git::is_stale_remote_ref_failure`) runs `git remote prune <remote>` and retries once; GHD shows the error. Flag: `252-prune-stale-refs-and-retry`.
- While a merge, rebase or cherry-pick is still conflicted (`RepositoryState::conflict_state`), the History tab's merge / rebase button is disabled and Branch › Merge into Current Branch, Squash and Merge, Rebase Current Branch and Update from Default Branch show an error saying to finish or abort it first (`Dispatcher::refuse_merge_while_conflicted`); GHD starts the operation and git refuses it. Flag: `838-no-merge-while-conflicted`.
- Create a New Repository warns "This directory contains a README.md file already…" when the README box is ticked and the target folder has a `README.md` (GHD keeps this warning behind `enableReadmeOverwriteWarning()`, beta builds only, so release builds overwrite the file silently). Flag: `219-readme-overwrite-warning`.
- Line counts for uncommitted changes (Corvane addition, off in the Corvane preset): every refresh also runs `git diff --numstat --no-renames -z HEAD` (the empty tree on an unborn branch) and counts the lines of untracked files (up to 1 MiB, not binary); each Changes row shows "+N -M" before its status icon and the "N changed files" header the totals of the listed files. Flag: `701-changes-line-counts`.
- The Changes list's "Ignore File / Folder / All .ext Files" items skip patterns the root `.gitignore` already has as a line (GHD `appendIgnoreRule` appends them again). Flag: `717-ignore-skips-existing-rules`.
- Stalled network operations (Corvane addition, off in the Corvane preset): with a timeout set, fetch / pull / push / clone / ls-remote run with `GIT_HTTP_LOW_SPEED_LIMIT=1` and `GIT_HTTP_LOW_SPEED_TIME=<seconds>`, so an HTTPS transfer that stalls fails with git's error instead of spinning forever (GHD sets no limit; SSH remotes are unaffected). The value is armed before each fetch, pull, push and clone. Flag: `254-network-stall-timeout`.

## Diff viewer

- The image "Difference" mode blends on the CPU (GPUI has no `mix-blend-mode`), at the two images' on-screen relative scale; it is recomputed when that scale changes.
- Text selection (`crates/corvane-ui/src/diff_view.rs` `TextSelection`; GHD uses the browser's selection over the rows): drag over the text, shift-click extends, ⌘A selects every row, ⌘C and the context menu's Copy put the lines on the clipboard without line numbers or +/- markers, one line per row (hunk headers included, as in GHD's DOM). In split mode the selection stays in the column the drag started in and copies only that side's lines (GHD's `selecting-before` / `selecting-after`). Differences: the highlight is a fixed colour per theme instead of the system selection colour, empty rows show no highlight, there is no double-click word / triple-click line selection, the selection is dropped when the file's diff or contents change (GHD keeps the DOM selection until the rows re-render; a refresh that reloads an identical diff keeps it in both), and dragging past the visible rows scrolls one line per pointer move rather than continuously.
- Tabs (`diff_view_rows::expand_tabs`; GHD keeps the tab in the DOM and applies CSS `tab-size` from Settings › Appearance › Tab Size on `#desktop-app-chrome`, `app/src/ui/app.tsx`): each tab in a diff row is drawn as four spaces, so tabs after other text do not stop at the next tab column and the Tab Size setting is stored but does not change the diff. Syntax spans, which the highlighter computes on the raw file lines (with GHD's fixed `tabSize = 4`, `side-by-side-diff.tsx`), are shifted through the same expansion.
- More languages than GitHub Desktop (Corvane addition): the default build's syntect set is syntect's defaults plus 330 TextMate grammars (Sublime Text, VS Code, Atom and TextMate bundles, via GitHub Linguist's license-checked collection) for languages neither the CodeMirror ports, syntect's defaults, two-face nor the tree-sitter grammars cover, converted to sublime-syntax and checked against Linguist's samples (`tools/tm-grammars/README.md`, `crates/corvane-highlight/assets/syntaxes.packdump`). GHD shows these files uncoloured. Not behind a flag: files GHD cannot highlight have no GHD behaviour to keep.
- Syntax highlighting (`crates/corvane-highlight/src/cm/modes`, ports of every CodeMirror 5 mode GHD's highlighter worker loads, proven token for token by `tests/cm_golden.rs`) differs from GHD only in cases no golden sample hits: GHD's sass mode throws on its second selector (no indent unit) and GHD then drops highlighting for the whole file, while the port leaves the rest of the file unstyled; slim `sub` blocks indented with tabs (GHD slices at a column); a handlebars comment or an elixir `%` literal delimited by a character outside the BMP (JS sees two surrogates); a U+2028 / U+2029 inside a line makes GHD's rust mode throw and its toml mode loop forever (GHD drops highlighting), while the ports keep going (`tools/cm-oracle/fuzz.py` proves every other mode matches GHD with those characters); regexes shared across modes treat U+0085 / U+FEFF as `\s` differently from JS, and case-insensitive `(?i)` word lists (powershell) fold `ſ` / `K` onto `s` / `k`; a markdown fence named after an `Object.prototype` member (`constructor`) crashes GHD and is a plain fence here.
- When highlighting happens (`crates/corvane-ui/src/diff_view.rs` `DiffView::highlight`; GHD tokenizes every diff in its highlighter worker, so a diff first shows uncoloured): tokens of the last 16 files are kept per side (old / new contents, highlighter), so revisiting a file or a reload that changed one side reuses them; with GitHub Desktop's tokenizers (CodeMirror ports, syntect), which run top down, the 200 rows from the top one on screen are coloured while the rows are built from each file's lines up to the last one they show (at most 192 KB; the same tokens the whole run gives, `tests/cm_golden.rs` `a_prefix_is_the_start_of_the_whole_run`), so the first frame is coloured, and both whole files are tokenized in parallel in the background for the rest; with tree-sitter, which parses whole files, or a bigger prefix, rows of the same file whose text did not change keep their previous colours until the background is done. A refresh (window focus, the filesystem watcher, after a git command) that reloads an identical diff leaves the view alone: rows, colours, expanded hunks, text selection and scroll position stay. Not behind a flag: the colours are GHD's, only sooner.
- Tree-sitter highlighting (Corvane addition, TODO decided 2026-09-30; `crates/corvane-highlight/src/treesitter`, grammars in `crates/corvane-grammars`): Settings › Appearance › Diff › Syntax highlighting offers "GitHub Desktop" (the default: the CodeMirror ports, syntect for other languages), "Tree-sitter for other languages" (the ports where GHD has a mode, tree-sitter before syntect) and "Tree-sitter" (tree-sitter wherever it has a grammar, then the ports, then syntect). 317 grammars (`docs/reference/tree-sitter-languages.md`): crates.io grammar crates, plus about 215 built from source at nvim-treesitter's pinned revisions (`tools/ts-queries/fetch.py`), with nvim-treesitter's queries where they compile against the pinned grammar, else the grammar's own, else Helix's (`tools/ts-queries/README.md`); capture names map onto the same thirteen `--syntax-*` colours by longest prefix, keeping CodeMirror's choices where it has one (numbers, operators and brackets in the line colour, `this`/`self` as keywords, preprocessor lines and doctypes as `meta`; `docs/reference/tree-sitter-captures.md`). Locals queries are not evaluated, so a parameter's later uses do not take its colour. The default build carries only the tree-sitter runtime: the grammars are native code in the `tree-sitter-all` / `tree-sitter-rest` packs (Settings › Advanced, or the Download button under the choice): one gzipped library per grammar package plus an `index.json`, so detection needs no library and a grammar is unpacked into `~/Library/Caches/Corvane/grammars/` and loaded with `dlopen` the first time a diff needs it (the app is signed without the hardened runtime, so library validation does not apply; a grammar's external scanner runs in-process, and a crash in one takes the app down); the full build links every grammar in. Flag: `105-tree-sitter-highlighting`.
- **Open in editor at a line**: the text context menu of a working-directory diff (unified and split) adds "Open in <Editor> at Line N" for the clicked row's new-file line when the selected editor ships a command line tool that can jump there (`editors::launch_at_line`: `code`/`codium`/`cursor`/`windsurf -g file:line`, Sublime Text's `subl file:line`, Zed's `cli file:line`); other and custom editors get no item. ## Performance

Engine choices that change no visible behaviour but make Corvane do less than GHD for the same action (measured with `tools/perf/bench.py`, `docs/perf.md`). The switchable ones are the Performance flags (`900` block).

- A refresh (window focus, the filesystem watcher, after git operations) runs its git processes at once, each on its own thread, and takes ahead/behind from `git status --branch` instead of a separate `git rev-list --left-right --count`; GHD runs them one after another. A refresh that finds nothing changed notifies nothing, so no view re-renders; the Changes busy spinner (`708-changes-busy-indicator`) is started by a dispatcher timer instead of the start-of-refresh re-render.
- Diffs of files with nothing staged run `git diff -- <path>` (index → working tree, which prints what `git diff HEAD -- <path>` prints when the index holds `HEAD`'s blob): git's `diff-index` walks the whole index for a pathspec and took 2.2 s on a 50,000-file index (git 2.54). Committed blobs (`<rev>:<path>`) are read in-process with gitoxide instead of `git show`, and gitoxide repository handles are kept per path while no configuration file changes (`corvane_git::handle`).
- `corvane_core::diff_cache`: a commit's changed files and committed diffs are kept by SHA (they never change), a working-directory diff with the status code, `HEAD` and the working file's size, mtime and inode (git's own change check; files written within the last second are not kept). Selecting a file or commit again, and the diff reload after every refresh, then need no git process and show in the same frame; the diff pane no longer blanks between selections. A refresh keeps the History pages already scrolled in when the first page is unchanged (GHD reloads the first 100 commits and drops the rest).
- Prefetch: while a file or commit is shown, the diffs of the next and previous files (and of the next three commits) are computed in the background, so ↑/↓ through the list shows each diff at once. Flag: `901-prefetch-diffs`.
- Filesystem watcher: each signal carries the time of the burst's last event, and a refresh that started after it (the one after Corvane's own commit, checkout, …) makes the watcher's refresh unnecessary, so it is skipped. With `902-fs-watcher-leading-edge` the first change after a quiet period refreshes at once and the rest of the burst once it settles (a save in the editor shows ~300 ms sooner). Flag: `902-fs-watcher-leading-edge`.
- After a `git status` slower than 0.5 s, `git update-index -q --refresh` runs once (at most once a minute per repository): status runs with `GIT_OPTIONAL_LOCKS=0` like GHD's and never saves refreshed stat data, so a checkout whose file timestamps changed without their contents (copied, restored, touched by a tool) re-read every such file on every refresh (6 s instead of 0.2 s on 50,000 files). Flag: `903-refresh-stale-index`.
- A commit in which every changed file is included whole skips GHD's `git reset -- .` before `update-index` (the reset only unstages what is staged again right after; one index rewrite fewer), and reads the new `HEAD` in-process instead of `git rev-parse HEAD`.
- Git LFS detection for the `InitializeLFS` prompt (`corvane_git::is_using_lfs_by_attributes`): reads the `.gitattributes` files in the index, the root one on disk and `info/attributes` for `filter=lfs`; GHD's `isUsingLFS` runs `git lfs track --json`, which walks every directory including untracked ones. A `.gitattributes` in an untracked subdirectory no longer counts. Flag: `905-lfs-detect-by-attributes`.
- Rendering: the diff views, the Changes and History sidebars and the selected commit are cached GPUI views (re-rendered only when they change, not for a caret blink, a hover or a scroll elsewhere); the branch list is a virtualized list (only rows on screen are built). GPUI patches (`vendor/`, "Corvane patch"): CoreText keeps sized fonts alive between lines (a fresh `CTFont` per shaped line rebuilt its glyph caches) and shaped lines stay cached for two more generations of 2,048 lines after they leave the screen (switching tabs or scrolling back reshapes nothing).
