# Deviations from GitHub Desktop 3.6.6

Features Corvane has that behave or look slightly differently from GHD, with the reason. Unbuilt features are in `TODO.md`; each module's doc comment also names its deviations next to the GHD file it ports.

## Flags

- Every deviation that can be switched off is a flag (`flags.md`, generated from `crates/corvane-core/src/flags/registry.rs`): a bullet below that ends with "Flag: `NNN-slug`" is controlled by that flag, and the **GitHub Desktop** preset turns all of them to their GHD-exact value. The rest of this file (engine, layout and platform decisions) stays fixed; `flags.md` lists them under "Not toggleable".
- The Flags dialog itself (`crates/corvane-ui/src/dialogs/flags.rs`, Corvane › Flags…, ⌘⇧,, `x-corvane://flags?q=`, `CORVANE_POPUP=flags[:query]`) is a Corvane addition with no GHD counterpart: search, category navigation, presets, per-flag Reset, a Relaunch bar for restart-required flags, Copy / Paste as JSON and `CORVANE_FLAGS`. `CORVANE_FLAGS` locks the flags it names for one session; the parity harness runs with `preset=github-desktop`. Each flag is a feature or a bug fix (`Nature` in the registry, tagged in `flags.md`); bug fixes are hidden from the dialog's list, search and counts unless its "Show bug fixes" checkbox (per dialog session, off by default) is ticked, while presets, Reset all and `CORVANE_FLAGS` still apply to them.

## GitHub layer

- **CI check runs**: GHES version gating (`lib/endpoint-capabilities.ts`) is reduced to GitHub.com vs. Enterprise (Enterprise gets no re-run and no Actions job steps). Views subscribe to a ref's status by touching it while rendering (`Dispatcher::touch_commit_status`, never notifies); a key nobody rendered for five minutes stops refreshing (GHD subscribes on mount / unsubscribes on unmount). Flag: `308-ci-status-idle-minutes`.
- **Pull request cache** is keyed by endpoint + `owner/name` in redb (`pull-requests:<key>`) with the head/base repositories embedded in each record; GHD keys IndexedDB rows by the GitHub repository's database id.
- **Push Branch Commits** (before a pull request is created): the base branch picked in Preview Pull Request survives the push (GHD's `onConfirm` drops it), and a failed push leaves its error on screen instead of opening the compare page anyway. Flags: `304-push-branch-commits-keeps-base`, `305-push-branch-commits-error-stops`.
- **Forks**: the repository's API `permissions` are refreshed on selection and after signing in (as GHD) and persisted with the repository. A push to a repository the user can only read opens `CreateFork` before git runs (GHD runs the push and offers the fork after the authentication failure); repositories whose permissions were never fetched still get the fork offer after a push refused with "Permission denied". The remote URL is not rewritten when the API reports a renamed repository (GHD `updateRemoteUrl`). Flag: `303-fork-before-push`.
- **Repository rules**: `useRepoRulesLogic` needs the account plan; an account stored before Corvane read it counts as paid until the launch refresh fills it in. The commit-message check merges the `Co-Authored-By` trailers with a port of `git interpret-trailers`' block rules instead of spawning git on every keystroke.
- **Re-authorization** (`workflow` scope, SAML SSO, invalidated token) opens the sign-in dialog (its default flow follows `307-sign-in-flow`) instead of GHD's browser flow; the push / failed action is retried after signing in, as in GHD.
- **Sign-in flows** (`docs/technical/oauth.md`): the device flow is the default (GHD only has the browser flow, with a bundled client secret). "Use the browser flow instead" runs GHD's web application flow with PKCE and a CSRF state over the `x-corvane-auth://oauth` callback (loopback `http://127.0.0.1:<port>/callback` for a bare binary or `CORVANE_OAUTH_LOOPBACK=1`); without `CORVANE_GITHUB_CLIENT_SECRET` at build time the token exchange relies on PKCE alone and GitHub may refuse it. Unverified live (no account on the development Mac). Flag: `307-sign-in-flow` (which flow the primary button starts; the other stays a link away).
- **GitHub Enterprise sign-in** (`ui/sign-in/sign-in.tsx`, `lib/stores/sign-in-store.ts`): GHD signs in to GHES in the browser with its own OAuth app. A GHES server does not know Corvane's github.com app, so the host needs an OAuth app its administrator registered (callback `x-corvane-auth://oauth`, Enable Device Flow for the device flow, GHES 3.1+). Its client ID comes from the sign-in dialog's "OAuth app" step (remembered per host in the store, client secret in the Keychain as `oauth:<client id>@<host>`) or is built in with `CORVANE_GHES_OAUTH=host=client_id[:secret],…`. With one, GHES offers the same device / browser / token choices as GitHub.com; without one, the dialog goes from the address straight to a personal access token, with a link to enter an app. Unverified live (no GHES instance).
- **Pull request notifications** (`corvane_core::notifications`, `corvane_platform::notifications`): posted through `UNUserNotificationCenter` with GHD's titles and bodies; the click handler follows GHD's app-store callbacks (select the repository when none is, then the review / comment / checks-failed dialog, or the CI popover when the pull request's branch is checked out). The notification's `userInfo` carries the dialog's data as JSON, so a click from an earlier session opens the dialog without GHD's API re-fetch. Posting needs the app bundle outside temporary directories (macOS answers "Notifications are not allowed for this application" for a bundle under `/private/tmp`).
- **Alive events** (`corvane_core::alive`, `corvane_github::alive`; GHD `alive-store.ts` + `notifications-store.ts` over `@github/alive-client`): one WebSocket subscription per signed-in GitHub.com account while Settings › Notifications is on, to the channel `/desktop_internal/alive-channel` names, with the offset kept across reconnects (exponential backoff capped at ten minutes; the JavaScript client's presence channels, shared worker and "Alive Redeploy" early reconnect are not implemented). Events are handled as in GHD: only the selected repository (a fork's parent when contributing upstream), only pull requests already in the cache, the review / comment / checks fetched from the API, checks-failed only for commits the account's emails authored and once per check suite. `CORVANE_POPUP=alive:<kind>[:api]` feeds a sample event through the same handler (sample review / comment / checks unless `:api`). Unverified live: no account exists on the development Mac, so the socket handshake against GitHub's Alive service has only been exercised by the frame parser's tests.
- **Test Notifications** (`dialogs/test_notifications.rs`, Help › Show Test Notifications in debug builds, `CORVANE_POPUP=test-notifications`): each button posts a sample notification at once (`corvane_core::samples`) instead of GHD's pick-a-pull-request / pick-a-review steps over the API, so there is no Back button; it works for repositories without a GitHub remote (a stand-in repository is used). As in GHD, test notifications ignore Settings › Notifications.
- **Pull request notification dialogs** (`PullRequestReview`, `PullRequestComment`, `PullRequestChecksFailed`, `crates/corvane-ui/src/dialogs/pull_request_notifications.rs`) open from a notification click, or with sample data through `CORVANE_POPUP=pr-review|pr-comment|pr-checks-failed|notification-click:<kind>`. "Switch to Pull Request" closes the dialog before switching (GHD spins in the header until the checkout is done); checks-failed shows the job steps the commit status store already has (no "Stand By" pane while logs load); re-running replaces the dialog, since Corvane shows one popup at a time.
- **Cherry-pick onto a pull request** (`pull_request_row` drop target, `Dispatcher::cherry_pick_to_pull_request`; GHD `onDropOntoPullRequest` + `startCherryPickWithPullRequest`): commits dragged from History onto a row of the Pull Requests tab are copied onto the pull request's branch, found the way a checkout finds it (a fork remote is added and fetched, `pr/<n>` created). Dropping on the checked-out pull request does nothing, as in GHD. When the branch cannot be determined GHD only logs and ends the operation; Corvane also shows the reason (Flag: `306-cherry-pick-pr-branch-error`). The cherry-pick operation starts at the drop (GHD starts it when the drag begins).
- **Pull request quick view** (`crates/corvane-ui/src/pull_request_list.rs`): the card is a fixed 400 px wide (GHD's `min-width`), shows the list item's "opened … by author" line next to the `#N` badge (Corvane addition), and is positioned from the card height measured on the previous frame instead of staying hidden until the Markdown iframe has loaded. Flags: `301-pr-quick-view-opened-by`, `302-pr-quick-view-width`.
- **Clone dialog** caches the repository list in redb per endpoint and filters it locally (as GHD does); there is no server-side search.
- **Clone dialog** resolution (`corvane_core::clone_info`): when every account answers 404 for an `owner/name` shorthand, Corvane shows GHD's "We couldn't find that repository" error (GHD passes the bare alias to git, which fails); when a lookup fails otherwise (offline, anonymous rate limit) the shorthand is cloned as `https://github.com/owner/name.git` (Flag: `204-clone-shorthand-not-found`). The account picker's filter is a fuzzy match on login and endpoint, and the list has no keyboard navigation.

## Repository

- Filesystem watcher (Corvane addition, `corvane_core::watcher`; GHD only refreshes on window focus and after its own actions): FSEvents on the selected repository's worktree and `.git`, debounced 300 ms, trigger a refresh. Flags: `202-fs-watcher`, `203-fs-watcher-debounce-ms`.
- Add Local Repository checks the path as it changes and keeps Add Repository disabled until it is a repository; GHD 3.6.6 checks only when Add Repository is pressed and leaves that warning up, stale, while the path is edited. Flag: `205-add-local-validates-while-typing`.
- The discard confirmation leaves out "Changes can be restored by retrieving them from the Trash" when every discarded entry is a submodule (nothing goes to the Trash); GHD 3.6.6 always shows it. Flag: `276-discard-submodule-no-trash-hint`.
- Import Repositories from GitHub Desktop (Corvane addition, off in the Corvane preset; File menu, a fifth button on the "Let's get started!" page when GitHub Desktop's data is on the Mac, `CORVANE_POPUP=import-ghd`): `corvane_platform::ghd_import` reads GHD's IndexedDB LevelDB files directly (write-ahead logs, sorted tables, snappy; newest entry per key, deletions honoured, GHD may keep running) and picks the `repositories` records out of the V8-serialised values; the dialog lists the ones still on disk that Corvane lacks, all ticked, and adds the ticked ones in GHD's order with their aliases. `CORVANE_GHD_DATA_DIR` points it at another GHD profile. Best effort: an unreadable file or a changed record layout yields fewer (or no) repositories, never an error. Flag: `206-import-from-github-desktop`.

## Tutorial

- The onboarding tutorial (`corvane_core::tutorial`, `crates/corvane-ui/src/tutorial_panel.rs`, `dialogs/tutorial_dialogs.rs`) follows GHD's assessor, panel, welcome / done pages, Start tutorial and Exit Tutorial dialogs and the blank-slate "Create a Tutorial Repository…" / "Return to In Progress Tutorial" button. Differences: the step is computed from the repository state when read (a pull request seen for the branch completes that step but is not persisted, GHD remembers it); the nudge arrows on the branch / push buttons and the commit button are not drawn; the panel is a fixed 350 px and the sidebar is not narrowed to leave the tutorial 650 px; the done page announces itself through a live region instead of focusing its heading; the README and texts say Corvane instead of GitHub Desktop (Flag: `103-product-name`).

## Markdown

- Markdown (release-notes pretext, pull request bodies, reviews and comments) is laid out natively by `crates/corvane-ui/src/markdown.rs` from a `pulldown-cmark` walk (`corvane_core::markdown`) instead of GHD's `marked` + DOMPurify output in a sandboxed webview. Headings, paragraphs, emphasis, strikethrough, inline and fenced code, links, lists, quotes and rules are styled after `static/common/markdown.css`; images show their alt text, tables become " | "-separated lines, raw HTML loses its tags. Text is not selectable, inline code keeps the paragraph size, and GHD's markdown filters (emoji, `@mentions`, `#123` / commit links, videos) are not applied; bare URLs are still linkified.

## Editor / commit form

- Spellcheck language follows `NSSpellChecker`'s automatic identification; there is no per-language picker and no Chromium-style "Ignore" item.
- Commit message templates (Corvane addition; GHD 3.6.6 ignores `commit.template`): the repository's resolved `commit.template` file, comment lines (`core.commentChar`) and outer blank lines stripped, prefills the description while the summary is empty and the description is empty or still the template; it comes back after every commit (`corvane_git::commit_template`). Flag: `201-commit-templates`.
- Detached HEAD (Corvane addition): the commit form shows a warning that the commit will not be on any branch, with a "create a branch" link opening Create Branch at HEAD; GHD 3.6.6 commits silently. Flag: `270-detached-head-commit-warning`.
- Opening several files (Corvane addition): with several changed files selected, the context menu's open items read "Open N Files in <editor>" / "Open N Files with Default Program" and open all of them (deleted files skipped); the changes list's own menu adds "Open All in <editor>" and a History file's menu "Open All Files of Commit in <editor>" (files still on disk). Disabled past 25 files. GHD 3.6.6 opens only the right-clicked file. Flag: `271-open-multiple-files`.
- Hiding files from the changes list (Corvane addition): changed files matching the flag's comma-separated, gitignore-like glob patterns (`corvane_core::filter::hidden_by`) are left out of the list, whose header then reads "N of M changed files". View only: hidden files keep their inclusion and are committed, without the "Hidden changes will be committed" warning. GHD 3.6.6 lists every file. Flag: `272-changes-hide-globs`.
- Recalling commit messages (Corvane addition): ↑ in the summary of an untouched commit form (summary empty, description empty or the commit template) fills in the latest commit's summary and description (`Co-authored-by` trailers dropped); further ↑ go back through the last 50 non-merge commits of the branch with distinct summaries, ↓ comes forward and past the newest restores the untouched form. Typing ends the browsing. GHD 3.6.6 has no message history. Flag: `273-recall-commit-messages`.
- "No local changes" with an open pull request for the branch (Corvane addition): a primary "View Pull Request" card ("Pull request #N is open for the current branch", the PR title, ⌘R) leads the suggested actions and opens it on GitHub; GHD 3.6.6 shows no pull request action then. Flag: `274-no-changes-view-pull-request`.
- Confirm commits to the default branch (Corvane addition, off in the Corvane preset): committing (not amending) while the repository's default branch is checked out opens "Commit to Default Branch" (Cancel / Commit); the unknown co-authors prompt still follows it. GHD 3.6.6 never asks. Flag: `275-confirm-commit-to-default-branch`.
- Commit summary length limit (Corvane addition, off in the Corvane preset): the summary takes at most 72 characters; the part of an edit past the limit is dropped (an HTML `maxlength`, applied after the edit since the kit's input has none). A recalled or amended message is not cut. GHD 3.6.6 has no limit. Flag: `277-summary-max-length`.
- The changes list's "Ignore All .x Files (Add to .gitignore)" items add the number of changed files with that extension ("Ignore All .png Files (170 Changed) (Add to .gitignore)"); GHD 3.6.6 gives no count. Flag: `278-ignore-menu-counts`.
- "Copy Diff" (Corvane addition) in the changes list's file context menu ("Copy Diff of Selected Files" for a multi-selection) copies the files' working-directory changes against HEAD as one `--binary` patch, untracked files diffed against `/dev/null` (`corvane_git::working_directory_patch`). The whole file is copied, whatever lines are selected for the commit. GHD 3.6.6 has no such item. Flag: `279-copy-diff`.
- The changes list's Filter Options popover has a sixth option, "Renamed files" (Corvane addition; GHD 3.6.6 has five). Flag: `280-renamed-files-filter`.
- Error dialogs have a "Copy" button (Corvane addition) putting the title and message on the clipboard, since the dialog text cannot be selected; GHD 3.6.6 offers no way to copy it. Flag: `281-error-dialog-copy`.
- File names only (Corvane addition, off in the Corvane preset): changes-list rows leave out the dimmed directory part of `PathText`; the filter still matches the whole path and the row's accessible name keeps it. Flag: `170-changes-file-names-only`.
- Changes list order (Corvane addition): a setting orders the list by path (GHD), by status (conflicted, new, modified, renamed / copied, deleted; path order within each) or by file name, case-insensitively; a filter text still ranks its matches best first, and ⇧-click / arrow keys follow the shown order. Flag: `282-changes-sort-order`.
- Changes filter matching (Corvane addition): a setting makes the filter text match as a substring, as the end of the path, or as the exact path or file name (case-insensitive, matches kept in list order) instead of GHD's fuzzy match. Flag: `283-changes-filter-match`.
- Commit author line (Corvane addition, off in the Corvane preset): a line above the commit summary reads "Committing as Name <email>" with the identity git resolves for the repository (`includeIf` included), or says which of `user.name` / `user.email` is missing. GHD 3.6.6 shows only the avatar. Flag: `171-commit-author-line`.
- Names invalid on Windows (Corvane addition, off in the Corvane preset): when an included, not deleted file's path has a reserved device name (`CON`, `nul.txt`, `COM1`), a character NTFS rejects (`<>:"\|?*`, control characters) or a component ending in a space or a dot, the commit form shows a warning naming the first one (`corvane_core::portable_paths`); committing stays possible. GHD 3.6.6 commits them silently. Flag: `284-windows-invalid-names-warning`.
- "Assume Unchanged" (Corvane addition, off in the Corvane preset): the changes list's file menu marks the selected modified / deleted tracked files `update-index --assume-unchanged`, so they leave the list; the list's own menu has "Stop Assuming Files Unchanged", clearing the mark from every file `ls-files -v` reports with it. GHD 3.6.6 has neither. Flag: `470-assume-unchanged`.
- A drafted commit message is cleared when a new newest commit of the branch, made outside Corvane, has the drafted summary (trimmed, exact); GHD 3.6.6 keeps the draft. Flag: `471-clear-message-after-outside-commit`.
- The "Committed … Undo" bar has a context menu (Corvane addition) with the History commit menu's HEAD items that fit there: Amend Commit…, Undo Commit…, Create Tag…, Copy SHA, View on GitHub. GHD 3.6.6 has none. Flag: `472-undo-bar-menu`.
- Tag field in the commit form (Corvane addition, off in the Corvane preset): a "Tag (optional)" field under the description (hidden while amending); after the commit lands, the name is created as a tag on it like History's Create Tag (joins the tags to push). Names over 245 characters are ignored. GHD 3.6.6 tags only from History. Flag: `473-commit-tag-field`.
- "Open With…" (Corvane addition) in the changes list's file menu for a single file (after "Open with Default Program"; not with several selected under `271-open-multiple-files`): the Repository › Open With… application picker, applied to the file. GHD 3.6.6 offers only the editor and the default program. Flag: `474-open-file-with`.
- Opening a folder in Visual Studio Code (Insiders), VSCodium, Cursor or Windsurf opens the folder's `*.code-workspace` file instead when there is exactly one at its top (`editors::code_workspace_file`); off in the Corvane preset. GHD 3.6.6 always opens the folder. Flag: `475-vscode-workspace-file`.
- A file manager other than Finder (Corvane addition): with an application set (name or path), Show in Finder and every Reveal in Finder item open the folder, or a file's parent folder, with `open -a <app>`; the labels keep "Finder". GHD 3.6.6 always reveals in Finder. Flag: `570-file-manager`.
- A browser other than the default (Corvane addition): with an application set (name or path), http(s) links open with `open -a <app> <url>` (every link goes through `Dispatcher::open_url`); other schemes, and a failed launch, fall back to the system handler. GHD 3.6.6 always uses the default browser. Flag: `571-browser`.
- Snoozing the discard confirmation (Corvane addition, off in the Corvane preset): with the flag at N minutes, Confirm Discard Changes has a second opt-out, "Do not show this message again for N minutes"; discarding files or lines in that repository then skips the confirmation until the time is up (session only). Discard All Changes always asks. GHD 3.6.6 has only the permanent opt-out. Flag: `476-discard-confirm-snooze`.

## Diff viewer

- The image "Difference" mode blends on the CPU (GPUI has no `mix-blend-mode`), at the two images' on-screen relative scale; it is recomputed when that scale changes.
- Text selection (`crates/corvane-ui/src/diff_view.rs` `TextSelection`; GHD uses the browser's selection over the rows): drag over the text, shift-click extends, ⌘A selects every row, ⌘C and the context menu's Copy put the lines on the clipboard without line numbers or +/- markers, one line per row (hunk headers included, as in GHD's DOM). In split mode the selection stays in the column the drag started in and copies only that side's lines (GHD's `selecting-before` / `selecting-after`). Differences: the highlight is a fixed colour per theme instead of the system selection colour, empty rows show no highlight, there is no double-click word / triple-click line selection, the selection is dropped when the diff changes (GHD keeps the DOM selection until the rows re-render), and dragging past the visible rows scrolls one line per pointer move rather than continuously.
- Tabs (`diff_view_rows::expand_tabs`; GHD keeps the tab in the DOM and applies CSS `tab-size` from Settings › Appearance › Tab Size on `#desktop-app-chrome`, `app/src/ui/app.tsx`): each tab in a diff row is drawn as four spaces, so tabs after other text do not stop at the next tab column and the Tab Size setting is stored but does not change the diff. Syntax spans, which the highlighter computes on the raw file lines (with GHD's fixed `tabSize = 4`, `side-by-side-diff.tsx`), are shifted through the same expansion.
- Syntax highlighting (`crates/corvane-highlight/src/cm/modes`, ports of every CodeMirror 5 mode GHD's highlighter worker loads, proven token for token by `tests/cm_golden.rs`) differs from GHD only in cases no golden sample hits: GHD's sass mode throws on its second selector (no indent unit) and GHD then drops highlighting for the whole file, while the port leaves the rest of the file unstyled; slim `sub` blocks indented with tabs (GHD slices at a column); a handlebars comment or an elixir `%` literal delimited by a character outside the BMP (JS sees two surrogates); a U+2028 / U+2029 inside a line makes GHD's rust mode throw and its toml mode loop forever (GHD drops highlighting), while the ports keep going (`tools/cm-oracle/fuzz.py` proves every other mode matches GHD with those characters); regexes shared across modes treat U+0085 / U+FEFF as `\s` differently from JS, and case-insensitive `(?i)` word lists (powershell) fold `ſ` / `K` onto `s` / `k`; a markdown fence named after an `Object.prototype` member (`constructor`) crashes GHD and is a plain fence here.
- Tree-sitter highlighting (Corvane addition, TODO decided 2026-09-30; `crates/corvane-highlight/src/treesitter`, grammars in `crates/corvane-grammars`): Settings › Appearance › Diff › Syntax highlighting offers "GitHub Desktop" (the default: the CodeMirror ports, syntect for other languages), "Tree-sitter for other languages" (the ports where GHD has a mode, tree-sitter before syntect) and "Tree-sitter" (tree-sitter wherever it has a grammar, then the ports, then syntect). About 100 grammars (`docs/reference/tree-sitter-languages.md`) with nvim-treesitter's queries where they compile against the pinned grammar, else the grammar's own, else Helix's (`tools/ts-queries/README.md`); capture names map onto the same thirteen `--syntax-*` colours by longest prefix, keeping CodeMirror's choices where it has one (numbers, operators and brackets in the line colour, `this`/`self` as keywords, preprocessor lines and doctypes as `meta`; `docs/reference/tree-sitter-captures.md`). Locals queries are not evaluated, so a parameter's later uses do not take its colour. The default build carries only the tree-sitter runtime: the grammars are native code in the `tree-sitter-all` / `tree-sitter-rest` packs (Settings › Advanced, or the Download button under the choice), loaded with `dlopen` (the app is ad-hoc signed without the hardened runtime, so library validation does not apply; a grammar's external scanner runs in-process, and a crash in one takes the app down); the full build links every grammar in. Flag: `105-tree-sitter-highlighting`.
- A diff whose only change is the file mode (`old mode` / `new mode` in the patch header, parsed by `corvane_git::parse_unified` into `DiffWarnings::mode_change`) says "The file mode changed from 100644 to 100755". GHD 3.6.6 (`ui/diff/index.tsx` `renderText`) says "No content changes found", or "Only whitespace changes found" while whitespace changes are hidden. Flag: `173-file-mode-change-message`.
- A renamed file's working-directory diff compares `HEAD:<old path>` with the working copy (`git diff -M HEAD -- old new`, `corvane_git::working_directory_diff`), falling back to GHD's diff when git does not pair the paths as one rename. GHD 3.6.6 (`lib/git/diff.ts` `getWorkingDirectoryDiff`) runs `git diff -- <path>`, index to working tree, so edits staged outside the app vanish. Flag: `174-renamed-diff-against-head`.
- With Diff Settings › Split selected, new, untracked and deleted files keep the unified layout at full width (`diff_view.rs` `render`), since one side of the split would be empty. GHD 3.6.6 (`ui/diff/side-by-side-diff.tsx`) splits them too. Flag: `175-unified-diff-for-added-files`.
- A changed symbolic link's working copy (`fileContents.newContents`, used for hunk expansion) is read as the link's target path with `read_link` (`corvane_git::working_file_lines`), the one line git diffs for a link. GHD 3.6.6 (`fileContents`, `ui/diff/side-by-side-diff.tsx` callers) reads through the link, which never returns for a link to a pipe or device and reads a huge target whole. Flag: `176-symlink-contents`.
- Diff font size (Corvane addition, off in every preset): the diff rows' monospace text can be set to 9–16 px (`diff_view.rs`, scaled by View › Zoom like everything else); rows stay 20 px tall. GHD 3.6.6 fixes it at 11 px (`styles/ui/_side-by-side-diff.scss`). Flag: `670-diff-font-size`.

## Settings

- Settings › Appearance › High Contrast (Corvane addition; GitHub Desktop has no high contrast theme): GHD's dark tokens in Primer's `dark_high_contrast` palette (`crates/corvane-ui/src/theme/ghd_high_contrast.rs`, table in `ghd-theme-tokens.md`). With the System theme, macOS's "Increase contrast" switches to it; the option is read when the system appearance changes and when Corvane's window becomes active. The fourth swatch's label wraps onto two lines. Flag: `101-high-contrast-theme` (off: three swatches, a saved High Contrast shows as Dark, "Increase contrast" is ignored).

- Notifications › permission hint only means something from the signed `.app` bundle (`UNUserNotificationCenter` needs a bundle); a bare binary shows no hint and posts nothing.
- Settings › Advanced › "Save crash reports locally" (Corvane addition, off by default) replaces GHD's crash reporter: a panic hook writes `~/Library/Logs/Corvane/crashes/<timestamp>.txt`, and the next launch lists those and macOS's `corvane*.ips` reports newer than the previous launch in "Corvane quit unexpectedly last time" (Reveal in Finder / Dismiss). Nothing is uploaded and the reports' contents are never read. Flag: `501-crash-reports` (off: no section, no panic hook).
- Settings › Copilot tab, Git › Hooks sub-tab and Advanced › Usage are omitted (see the module doc of `dialogs/preferences.rs`).
- Settings › Prompts has no "Overriding commit message with generated message" checkbox (a Copilot prompt). Settings › Advanced holds Corvane's extra sections (crash reports, optional components), so its tab content scrolls within GHD's 440 px minimum height instead of growing the dialog.
- Settings › Advanced › Optional components (Corvane addition, PLAN.md §3.7; GHD ships every grammar): the `syntax-extended` pack (two-face's full grammar collection as a syntect dump) is downloaded from the signed `packs-manifest.json` of the latest GitHub release into `~/Library/Application Support/Corvane/packs/<name>/<version>/`, sha256-checked, and swapped into the highlighter at once; Remove falls back to syntect's built-in set. The `full` cargo feature compiles the collection in and the row says "Included in this build". With `105-tree-sitter-highlighting` on, the section also lists the `tree-sitter-all` / `tree-sitter-rest` grammar packs (per-platform manifest entries with a `target`; a manifest entry of a kind a build does not know is skipped). `corvane_packs` also understands `git-portable` / `git-lfs` entries, which are not published yet (TODO.md). Flag: `502-optional-components` (restart required; unavailable in the `full` build).

## Blank slate

- Signed in, "Let's get started!" shows the account's repositories beside the actions as GHD does (`crates/corvane-ui/src/no_repositories.rs`, list and `AccountPicker` shared with Clone a Repository in `cloneable_repositories.rs`). Differences: while the list shows a message (loading, no match, no repositories) GHD's section shrinks to the message's intrinsic width and re-centres, Corvane keeps the two half-width panes; the filter's fuzzy match highlights approximately the characters fuzzaldrin-plus picks (it sometimes marks a second run); the list has no keyboard navigation from the filter and Enter does not clone (see `TODO.md` › Accessibility); GHD's list goes blank behind the account popover, Corvane's stays drawn.

## Welcome

- Configure Git with an account follows `ConfigureGitUser`: "Use my GitHub account name and email address" (the first account's name read-only, its emails in a `Select`) or "Configure manually" (with `GitEmailNotFoundWarning`). The preferred email (`lookupPreferredEmail`) knows only whether the primary address is private, not every address's visibility, and falls back to the first address; the manual fields keep their text when Configure Git is left and entered again (GHD remounts the form and prefills it anew).
- The Welcome flow (`crates/corvane-ui/src/welcome.rs`) matches GHD's layout at the 1.2 welcome scale. Differences: texts name Corvane (Flag: `103-product-name`); the start footer's second paragraph states that Corvane sends no usage metrics (GHD's links to its metrics page), worded to fill the same two lines so the content stays put; the scale is fixed at 1.2 instead of following GHD's viewport media queries (1.3 at ≥ 1400×725, …).

## Illustrations

- GPUI has no CSS filters, so GHD's dark-theme `.blankslate-image` filter (`invert() grayscale(1) brightness(8) contrast(0.6)`) is baked into copies under `assets/illustrations/dark/` by `tools/illustrations/darken.py` (flat colours only, which is all the `empty-*`, `paper-stack`, `multiple-files-selected` and `ufo-alert` SVGs use).

## Window / menus

- Move to Applications prompt: the backdrop dismisses it (GHD: `backdropDismissable={false}`; Flag: `403-move-to-applications-backdrop-dismiss`); the move never asks for administrator rights, so it fails with the error when `/Applications` is not writable (Electron can authorize).
- About › License and Open Source Notices lists the Rust crates in the macOS build (`cargo about`, regenerated by `packaging/acknowledgements.sh`); license texts are not selectable. GHD's "Terms and Conditions" link is omitted (GitHub's terms do not apply to Corvane). The About dialog also has no Beta Channel paragraph or Copilot link, and adds a "Source code" link under the license notices and the CPU architecture after the version (both Corvane additions, Flag: `402-about-extras`); development builds show GHD's "running in development" text and no Check for Updates button.
- Install Command Line Tool… links `Corvane.app/Contents/Resources/corvane` (`packaging/corvane.sh`) to `/usr/local/bin/corvane` as GHD does with `github`, asking for administrator rights through `osascript` when needed. `corvane [open] [path]` and `corvane clone [-b branch] <url|owner/name>` (GHD `cli/main.ts`) hand an `x-corvane://openLocalRepo/<path>` / `x-corvane://openRepo/<url>?branch=` URL to Corvane.app with `open -a`, so a running Corvane receives it (GHD passes `--cli-open` / `--cli-clone` to a second instance). GHD 3.6.6's URL parser has no `openLocalRepo` action. `--open-repo <path>` is still understood at launch.
- `x-corvane://` URLs (`corvane_core::app_url`, GHD `parse-app-url.ts` + `dispatchURLAction`): an `openRepo` whose repository is not added opens the clone dialog prefilled and continues with the branch / pull request / file once that clone finishes, as GHD's `_startOpenInDesktop`; `pr=` needs a signed-in account to fetch the pull request. `oauth` URLs are parsed but ignored (no browser sign-in, TODO.md).
- Finder › Services › "Open in Corvane" (Corvane addition, `corvane_platform::services`): an `NSServices` entry for folders whose provider turns the picked path into the `openLocalRepo` URL.
- Help › Show Release Notes (Corvane addition; GHD shows the dialog only after an update) opens the `ReleaseNotes` dialog for the running version from the GitHub Releases API. Release bodies are Markdown: `[Kind]` list items are classified as in GHD, untagged items by their `##` heading (GHD drops them), entries are plain text instead of `RichText` (`crates/corvane-core/src/release_notes.rs`). "Install and Restart" appears only for the notes of an update the self-updater has ready. Flags: `401-release-notes-menu-item`, `504-release-notes-heading-kinds`.
- Self-updater (`corvane_platform::updater`, `corvane_core::updater`, PLAN.md §3.8; GHD: Electron `autoUpdater` + Squirrel): GitHub Releases is the feed, the `.zip` is minisign-verified and swapped in for the running bundle on "install and restart" (GHD installs at the next launch on its own). The banner reads "Corvane N is available. See what's new or install and restart." instead of GHD's "An updated version … will be installed at the next launch"; "what's new" shows only the latest release's notes (GHD merges every release since the running version); there is no prioritised-update variant (`x-prioritize-update`), no showcase banner and no `InstallingUpdate` dialog (the swap takes well under a second). A Homebrew-installed bundle is told to `brew upgrade corvane`. Checks run in release builds only (GHD: not on the development channel), at launch after a 15–60 s jitter and every four hours; About shows GHD's update status lines and "Check for Updates" / "Quit and Install Update", plus the architecture after the version. Errors from background checks are only logged (GHD posts them too; Flag: `503-quiet-background-update-errors`). `packaging/release.md` documents the keys.
- View › Zoom In ⌘= / Zoom Out ⌘- / Reset Zoom ⌘0 (GHD `zoom(ZoomDirection)` over Electron's page zoom, `ZoomInFactors` 0.67…2, `#window-zoom-info`): GPUI has no page zoom, so every size in `corvane-ui` goes through `theme::sizes::zpx` and one factor (`theme::sizes::zoom_factor`, persisted as `window_zoom_factor`, `CORVANE_ZOOM=<factor>` for a session). Persisted widths (sidebar, file lists, toolbar buttons) are kept in CSS pixels as in GHD. Differences: scrollbars keep their system size (Chromium scales them with the page), gpui-kit controls scale their font size and corner radius but not every inner padding, the window's minimum size and the traffic-light offset stay in screen pixels, the "125%" pill holds for 750 ms without GHD's 100 ms scale/fade transitions, and lists that measured their rows re-measure on the next frame (a one-frame flash of the old heights is possible).
- View › Expand / Contract Active Resizable (⌘9 / ⌘8) resize the focused pane by GHD's 5 px and announce GHD's "<description> width increased. Set to N%" through a polite live region; the percentage is that of the new width (GHD reads the width before applying the step, so its number lags one step; Flag: `601-resizable-announces-new-width`). The commit, stash and pull request file lists take keyboard focus when clicked so the items apply to them (`crates/corvane-ui/src/active_resizable.rs`).
- A deleted linked worktree falls back to its main worktree as in GHD (`recoverMissingWorktree`), but Corvane records the main worktree path on every refresh rather than only on a worktree switch, because `git worktree remove` also deletes the metadata GHD's fallback reads. Repository entries saved before this cannot recover and are flagged missing ("Can't find").
- Missing repositories (`crates/corvane-ui/src/missing_repository.rs`, GHD `MissingRepository`): "Can't find "<name>"" with Check again, Locate…, Clone Again (GitHub repositories) and Remove (no confirmation, from the view, the Repository menu or the list's context menu, as GHD) replaces the repository view, and the toolbar keeps only the repository button with the alert icon. Every refresh of a missing repository (focus, Check again, selecting it) probes the path again, as GHD's `_refreshOrRecoverRepository`. Repository › Open in *editor* and Open With… stay enabled for a missing repository (GPUI enables app-level actions by their handler; GHD disables both).
- Unsafe repositories ("detected dubious ownership", `crates/corvane-ui/src/missing_repository.rs`, GHD `MissingRepository` + `getRepositoryType`): detected from the failing git call itself (every refresh, and any action error that reaches `Dispatcher::show_error`) rather than a `rev-parse` probe when adding or switching; the repository is flagged missing as in GHD and shows "<name> is potentially unsafe" with the directory git named, Trust Repository (`git config --global --add safe.directory`) and Remove (no confirmation, as GHD). Its main worktree is still recorded, read by gitoxide (which opens such repositories with reduced trust), where GHD skips it because git will not run.
- Worktree toolbar button appears only with linked worktrees (or while its foldout is open), as in GHD.
- Resizable toolbar buttons (`crates/corvane-ui/src/toolbar.rs`, `corvane_core::toolbar_widths`): the worktree and branch buttons resize as in GHD; the push/pull button keeps its 230 px (GHD resizes it too), the handles do not take ⌘9 / ⌘8 or announce the new width, and the width is saved when the drag ends rather than on every move (Flag: `404-toolbar-width-save`).

## Keyboard

Audit against GitHub's Desktop shortcut table and GHD's `List` / `FilterList` / `Dialog` key handling (2026-09-29). Every menu shortcut in the table has its binding (`crates/corvane-ui/src/keymap.rs`), including ⌘0 / ⌘= / ⌘- zoom and ⌘8 / ⌘9. Lists: ↑ / ↓ move, ⇧↑ / ⇧↓ extend the selection (changes and history), ⌘↑ / ⌘↓ and Home / End jump to the first / last row, Space includes or excludes the highlighted files, ⌘A selects every file, Escape closes foldouts and dialogs, ⌘F focuses the filter, ⌘Enter commits from the message. Differences: the repository, branch, pull request and worktree foldouts filter as you type but ↓ does not move into the list and Enter does not pick the single match (GHD `FilterList`); PageUp / PageDown do not page through lists; a dialog's default button is not triggered by Enter unless a text box handles it; Shift+F10 does not open the selected row's context menu; Tab does not walk the toolbar buttons and list rows (GPUI focus stays on the pane); ⌥⌘I (Developer Tools) has no equivalent.

## Accessibility

- List rows (repositories, branches, pull requests, changes, history, stash and commit / pull request file lists, worktrees) are `Row` nodes (macOS `AXRow`) named with their visible text and status (`widgets::ListRowA11y`); GHD uses `role="option"` rows in a `listbox`. Each list is a `List` node (`AXList`) owning its rows, named after GHD's `ariaLabel` where it has one ("Commits", the "N changed files" header) and otherwise "Repositories", "Branches", "Pull requests", "Worktrees" or "Changed files". Banners are polite live regions announced when they appear.
- Repository Settings › Git Config labels its lone email text box "Email"; GHD's `GitConfigUserForm` drops the label whenever the email isn't a signed-in account's address (so always when signed out), although its comment says the label should only go under the account-email dropdown's "Other". Flag: `602-git-config-email-label`.

## Lists

- A selected row keeps its selection colour while the pointer is on it. In GHD `.list-item:hover` outranks `.list-item.selected` by specificity, so in an unfocused list the selected row takes the hover colour and looks unselected until the pointer leaves; only the focused list's active selection survives hover. Flag: `104-selection-keeps-colour-on-hover`.
- ⇧-click in the changes list keeps rows ⌘-clicked outside the range: it replaces only the range from the anchor (the last clicked file) to the previous ⇧-click, as Finder does (`list_selection::extend_keeping`). GHD 3.6.6 selects the range alone. Flag: `172-shift-click-keeps-selection`.

## Scrolling

- Scrollbars reproduce Chromium's macOS scrollers (`crates/corvane-ui/src/scrollbar.rs`), overlay or legacy as `NSScroller.preferredScrollerStyle` says. Mouse-wheel ticks are animated with Chromium's smooth-scroll curve; Electron on macOS only does that when `NSScrollAnimationEnabled` is set, so GHD usually jumps 40 px per tick. Flag: `102-smooth-wheel-scrolling`.
- The diff list estimates rows it has not rendered yet at one line (20 px), so the thumb can shift slightly as wrapped lines come into view; GHD's react-virtualized list estimates too.
